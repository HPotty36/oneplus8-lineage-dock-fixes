# 남은 과제

우선순위 순. 각 항목에 지금까지의 근거와 다음에 해볼 실험을 적었습니다.

## 1. 충전기가 꽂힌 독에 폰을 연결할 때 가끔 키보드만 안 잡힘

- **빈도**: v3·v4·v5에서 같은 시나리오 3회 중 1회 실패 (v5, 독을 뒤집어 연결한 경우).
- **증상**: 첫 번째 허브(`214b:7250`)와 VIA USB2 허브(`2109:2815`)는 잡히고 마우스도 됨.
  VIA 허브 뒤 키보드는 `device descriptor read/64, error -32` → `error -71` → `unable to enumerate`.
  같은 VIA 허브의 LAN도 안 나오고, 키보드를 다시 꽂아도 VIA 허브가 포트 변화를 보고하지 않음.
- **임시 해결**: 독에서 충전기를 뺐다 다시 꽂기 (독 전원이 리셋되면서 모두 복구).
- **가설**
  - 이 경로에서는 폰이 처음에 sink(UFP)로 붙기 때문에, DR_Swap으로 호스트가 되기 전에
    OPLUS charger-ID 스위치가 한 번 켜졌다 꺼짐 (`set value:1` → `set value:0`, 약 80ms).
    지금 패치는 DFP일 때만 생략하므로 이 순간은 막지 못함. 이때 D+/D-가 끊기며 VIA 허브가 이상 상태로 들어갈 수 있음.
  - 키보드(QMK 펌웨어)가 전원이 유지된 채 호스트가 갑자기 사라지면 다음 인식에 실패하는 문제.
  - 플러그 방향에 따른 차이 (실패한 1회만 뒤집어 연결).
- **다음 실험**
  - 상대가 PD 파트너이고 DP Alt Mode를 지원하는 독이면 UFP 상태에서도 charger-ID 스위치를 생략.
  - 같은 방향·반대 방향으로 각각 여러 번 반복해 재현율 확인.
  - 실패 상태에서 VIA 허브(`1-1.2`)만 리셋해 보기 (`USBDEVFS_RESET` ioctl, 또는 sysfs `authorized` 0→1 토글).

## 2. 충전기가 꽂힌 상태에서 독의 유선 LAN이 안 잡힘 (USB 2.0 전용 모드)

- 폰이 source일 때(충전기 없음)는 LAN이 `1-1.2.3`으로 잡히지만, 폰이 sink일 때나 PR swap 이후에는 나오지 않음.
- 현재 Wi-Fi를 쓰므로 보류. 1번과 같은 VIA 허브 문제일 가능성이 높음.

## 3. 충전기를 쓰면서 USB 3.0 살리기

지금은 `host_hs_only=1`로 USB 3.0을 꺼서 안정성을 얻은 상태. 충전기를 쓰는 경우 USB 3.0은 원래도 거의 동작하지 않았음:

| 상황 | USB 3.0 |
|---|---|
| 충전기 없이 연결 | 정상 |
| 충전기가 먼저 꽂힌 독에 연결 | 링크 학습 실패 (`Cannot enable` 4회, 약 16초 동안 USB 2.0 인식도 지연) |
| 연결 후 충전기 꽂기 | 링크는 유지되지만 VIA 허브 뒤 키보드가 멈춤 |

- **가설**: 독이 이미 전원을 받고 있으면 VIA 허브의 USB3 업스트림 포트가 호스트 없이 오래 대기하다 이상 상태(Compliance 등)로 들어감.
  폰이 source로 붙을 땐 호스트가 즉시 시작되지만, sink로 붙으면 DR_Swap까지 0.5~1초 늦게 시작됨.
- **다음 실험**: SS 포트 warm reset 재시도, sink 경로에서 QMP PHY를 미리 켜지 않기, PR swap 직후 USB3 쪽만 강제 재연결해서 VIA 두 쪽을 맞추기.

## 4. 루트 포트 재확인(hub.c) 동작 검증

- 라운드 1 단계 3, 라운드 4 단계 5처럼 "인식 도중 PR swap으로 끊긴 뒤 다시 안 찾는" 경우를 위해 넣었지만,
  마지막 테스트에서는 이 상황이 재현되지 않아 `enumeration interrupted, re-checking port` 로그를 아직 못 봤음.
- 다음 테스트에서 이 로그가 나오는지, 나온 뒤 실제로 다시 잡히는지 확인 필요.

## 5. LineageOS 업데이트 후에도 유지되게 하기

- 업데이트는 boot 파티션을 덮어써서 커널 수정이 사라짐 (`/data/local.prop` 지문 설정은 유지).
- 방법
  - 업데이트마다 새 boot 이미지에 이 커널을 다시 넣기 (커널 소스가 바뀌었으면 다시 빌드).
  - **LineageOS Gerrit에 패치 올리기** — 아래 세 개는 버그 수정이라 받아들여질 가능성이 있음:
    1. DR_Swap 시 `peer_usb_comm`과 무관하게 호스트 시작 (`policy_engine.c`)
    2. 호스트 모드에서 charger-ID / VOOC 스위치 생략 (`oplus_battery_msm8250.c`, `oplus_vooc_fw.c`)
    3. PR swap 종료 시 DRP 복구 (`oplus_battery_msm8250.c`)
  - autosuspend 끔, USB 2.0 전용은 이 독에 맞춘 우회책이라 기본값으로 올리기는 어려움 (모듈 파라미터 형태로만 제안 가능).

## 6. 기타 확인할 것

- `usbcore.autosuspend=-1`의 배터리 영향 측정 (독 연결 중에만 의미가 있을 것으로 예상).
- Android clang(r596125)으로 빌드해 컴파일러 차이 배제 (지금은 Ubuntu clang 18.1.3).
- 충전기 분리 시 xHCI 정리에 5초가 걸리는 경우 (`connect-debounce failed`)가 있음. 동작에는 문제없지만 원인 미확인.
- 이 작업 전에 보던 "충전기 연결 시 멈춤" 현상이 이번 수정 후에도 재현되는지 다시 확인.
